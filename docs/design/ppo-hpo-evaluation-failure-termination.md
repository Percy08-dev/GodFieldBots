## Core failure cleanup

The tuple/list error currently occurs after actual prepared publication exists,
before GroupPack's schema guard enters its ordinary try/revoke handler. Merely
closing packed collection may leave that prepared owner's control reservation.

The HPO-only core failure handler must retain and revoke that SAME actually
prepared publication/composite owner using its existing revoke method, then
independently perform existing task joins and packed Writer/executor/original
closure. Attempt all reachable cleanup even if one fails; preserve the initiating
exception and every actual uncertain owner. Do not change general Pack APIs,
revoke a committed/foreign owner, discard original failed evidence or report
cleanup complete from absence of errors alone.

The observation's retirement check recomputes original concrete states: all
registered tasks settled; each created group environment's actual
storage_cleanup_complete(result) (including server/process/drainer retirement);
actual prepared publication cleanup_complete; actual packed closure and Writer/
executor/future/pool/control reservations retired. It also binds the returned
result or original SAME exception identity. Successful evidence must come from
this actual invocation; uncertainty/partial construction refuses confirmation.

## Outer failed operation

Primary and comparison evaluation outer owners retain the observation and all
actual Source/verifier/artifact/pin owners. On failure:

1. Preserve the original exception. Attempt every actual artifact/verification
   Source close and every acquired pin release, including both comparison parents.
   Check actual released states and typed matching release receipts. A verifier
   constructor/close uncertainty must remain visible through its reachable owner.
2. While the SAME GpuJob capability is still held and open, require the original
   observation's positive core retirement, actual Source/artifact closure and all
   exact pin release receipts. Then call the existing confirm_termination, whose
   audited token proofs still require actual never-started/reaped observations.
   Empty ledger, PID absence, elapsed time, lock release or error-attribute
   absence alone never permits this path.
3. Persist only a distinct failed-operation operational termination record linked
   to the actual global receipt. Rethrow the original error. Do not write a seed
   evaluation receipt, accepted matchup/projection, aggregate/objective or
   successful tell. Failure records remain authoritative.
4. If cleanup is uncertain or global termination publication fails, leave the job
   unconfirmed/poisoned, keep primary error plus exact cleanup owners/notes, and
   block further GPU work. If only the local copy fails after actual durable
   global termination, retain the actual receipt on the primary exception and
   report the copy failure; do not turn it into data success.

This preserves the accepted distinction between GPU resource termination and
data qualification. It prevents avoidable admission-only jobs for fully proved
failure cleanup without relaxing recovery of genuinely unconfirmed jobs.
