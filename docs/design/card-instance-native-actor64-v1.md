# Native Actor64 retained-source handoff — design v1

Status: proposal for Root/architecture review; **no production implementation authorized by this document**. Based on accepted ADR0024 §18.2, current `CardInstanceNativeSession`/`StructuredSessionBridge`, accepted retained `FormalGameParent`, and the Actor64 closed collection-role leaf. MAIN remains untouched. Separate marker `card_instance_final_validation='collection5-final64;journal6;codec2'` stays absent; neither formal controls nor fixture tokens substitute for it.

## Ownership and closed role

Add an internal `CorrectedCollectionRole::{PpoBatch16, FinalValidation64}` argument to the SAME corrected collection traversal. Existing entrypoints default to PpoBatch16 with byte-identical controls, outputs, qualification and lifecycle. FinalValidation64 uses Collection5 `collection_role='ppo-final-validation'`, split validation, 32 swapped pairs, 64 episode identities and exactly 64 selected own-participant natural endpoints, including zero-decision endpoints. Both participants' originals are structurally validated; only the selected participant's inputs are exported. Canonical/server diagnostics remain opaque file hashes. No engineering Collection4/TreeSourceKind substitution, fixture-purpose conversion, PPO16 padding, GAE, numeric permit, update or issuer.

`CardInstanceNativeSession` retains one final-validation slot beside its already-authorized historical parent core. It borrows that SAME core's parent Sources, budget, Control, binary evidence and original lineage; it never reopens/rebaselines the parent. The slot is not another parent/coordinator or a source of qualification. Existing session finalize/close must account for a reachable slot and cannot report parent retirement while slot retirement is unconfirmed. Root's ordinary source alias integration is preserved; no copy of `_game_manifest` returns.

## Four additive methods on the existing class

Use the existing ABI's `retained_python_bytes` spelling, `CancelHandle`, executor serialization/GIL-detach rules and typed-bank tuple exporter. These methods do not belong on `StructuredNativeSession` or fixture classes.

1. `inspect_final_validation(request: bytes, retained_python_bytes: int = 0) -> bytes`: strict canonical JSON request below; inspect originals and retain final slot. Returns canonical summary JSON. Pure mode/phase/type refusals leave parent unchanged; after admission, set slot Failed before fallible work, advancing to Inspected only on complete success.
2. `export_final_validation(episode_index: int, retained_python_bytes: int = 0) -> (metadata_bytes, uint8_banks, int64_banks, float32_banks)`: exactly the existing four-tuple ABI with read-only owned 1D NumPy banks, descriptor schema and ExportLease/base owner. Export the next selected ordinal only (0..63, no skipping/replay). This per-episode parameter is an explicit refinement of the earlier four-method sketch, bounding DTO/raw copies without retaining 64 exported packets. Return only after that packet's Stage disk retirement/join succeeds. A packet/export/quota/wrapper failure exposes no partial payload and makes the slot cleanup-only.
3. `recheck_final_validation(retained_python_bytes: int = 0) -> None`: full retained parent, binary, final originals/inventory, ancestor, manifest-kind and pending-evidence guards; no refreshed baseline, new permission or deadline extension. Failure is sticky. Use existing `used_bytes()`/`peak_bytes()` for aggregate accounting rather than new counters/owners.
4. `close_final_validation() -> None`: cleanup-only callable after failure, expiry or cancellation. On healthy use, final guards first; retire slot work/core/Stage and join, then relinquish the collection loan. Outstanding packet leases must be released before healthy close; a failed close keeps SAME reachable owner and first error. Confirmed repeated close is memory-only/idempotent. Empty cleanup retries cannot convert uncertain retirement into confirmation. Parent close still uses its existing real session/executor and lock confirmation.

### Request v1 (exact top-level keyset)

`{schema_version:1, kind:'card-instance-final-validation-request', parent_run_sha256, directory, manifest, expected_plan, returned_report}`.

* `parent_run_sha256`: exact existing retained parent run hash; never an alternate parent path. `directory`: absolute nonsymlink original collection path, distinct from parent controls/numeric roots, with ancestor identity guards.
* `expected_plan` exact keys: `linkage`, `config_projection`, `validation_invocation`, `schedule`, `policy_bindings`. These are immutable values from SAME Python `GameFinalValidationPlan`, not authorization flags. Python continues independently computing its final schedule/final binding; Rust checks original equality plus SAME parent/final artifact and all role/structural controls. Native success alone cannot establish that the caller owns the Python plan.
* `linkage` exact nine keys: `parent_run_id,parent_run_path,batch_id,final_generation,final_inference_sha256,policy_label,learner_seats,schedule_digest,policy_registry_digest`. Batch is `validation-final`; generation 0..1000 at structural level, matching complete formal parent's positive update count at owner admission. Final manifest digest/label must match retained final inference and full neural metadata, not merely caller values.
* `config_projection` exact keys: `recipe,parent_config_sha256,parent_config_inputs_sha256,projected_config_sha256`; recipe `run-split-train-to-validation-v1`. Derive expected projected Config from original parent by changing ONLY `run.split`; preserve original Config input byte origins and code identity.
* `validation_invocation` exact keys: `started_unix,started_monotonic,caller_deadline_monotonic,admission_deadline_monotonic,execution_deadline_monotonic,wall_deadline_monotonic`. Reproduce current `validation_invocation`/`checked_invocation` numeric types, arithmetic/order and literal7200/5400/7140/60 budgets. Child execution deadline is additionally bounded by the existing retained parent/native Control deadline; no old deadline is extended.
* `returned_report`: null for canonical read-only reopen; exact returned report object for SAME pending live collection. Use the existing closed report schema, preserving every field; persisted report.wall <= manifest.elapsed_seconds <= returned report.wall <= capped invocation duration and all non-wall report fields equal. Healthy/comparison-valid, all64 natural and no failure/health evidence are required. No flags in this request grant collection publication or formal eligibility.

### Manifest variants (exact keysets; no filename argument)

* Canonical: `{kind:'canonical'}`. Read ONLY `manifest.json`; reject pending-control substitutions, symlinks, changed inventory and incomplete publication.
* Pending: `{kind:'issued-pending', evidence:{directory_identity,file_identity,bytes,sha256}}`. `directory_identity` has exactly `device,inode`; `file_identity` exactly `device,inode,mode,size,mtime_ns,ctime_ns`; `bytes` is the exact byte count (must equal size), not embedded payload; hash is lowercase SHA256. Read ONLY `manifest.json.tmp`, and require canonical `manifest.json` absent. Native verifies independently opened file/directory identity, strict bytes/hash, all originals and exact inventory using that fixed control name. It retains its own Source evidence/read handle; it never consumes, duplicates, closes, seeks or modifies the publisher's write descriptor.
* Python creates pending evidence ONLY after concrete `_IssuedFinalValidationCollection.require(SAME context)` and `manifest_name()` returns literal `manifest.json.tmp`. Open a separate no-follow read handle under the retained safe directory, record fstat identity, bounded hash/size with before/after fstat, close it before returning/yielding, then repeat actual issued/publication guards. Native independently opens/checks the same path. Retain actual issued token in the Python Source throughout use. Before each phase and final cleanup, repeat its guard and native evidence recheck. No callback, arbitrary filename, serialized token or JSON `issued:true` is accepted as authority. The original publisher alone performs finish/revoke, after all Source/context/parent cleanup required by ADR.

### Inspect reply v1 (exact keys)

`{schema_version:1,kind:'card-instance-final-validation-summary',parent_run_sha256,directory,manifest_kind,manifest_sha256,source_set_sha256,linkage,config_projection,validation_invocation,elapsed_seconds,games,selected_decisions,zero_endpoint_games,episodes,qualified,parent_qualification}`.

`games=64`, `qualified=false`, `parent_qualification='not_performed'`; `manifest_kind` is canonical/issued-pending. `episodes` is ordered final schedule selection, each exact `{episode_index,episode_id,game_id,viewer,decisions,end_kind,outcome,episode_digest}`; natural outcome/digest/perspective come from actual selected originals. Episode digest uses SAME Python `_episode_correspondence_digest` field/order recipe, not an ad-hoc native hash. This summary is structural evidence; Python's SAME parent/plan/source guard remains authority.

## Genuine EpisodeRecords and raw token packet

Current `ParsedJournal` drops accepted decision document/table after `Stage.frame`; correspondence bindings retain payload SHA, not full payload. Therefore do NOT claim existing raw tokens can reconstruct original DTOs. Inspect validates all64 with no full-cohort DTO/token spool. Per-episode export reuses the existing §17.2 `Journal::restage_corrected` pattern on that selected journal's SAME retained participant Sources, bracketed by full original guards, then compares proof/digests/semantics/correspondence to the inspected facts. This is the SAME Rust parser on retained originals, not an independent reader or refreshed baseline; there is no Python journal read. Only the current episode owns a Stage. For FinalValidation64 ONLY, at that SAME accepted-decision staging point, project the whitelist below to a private DTO spool before releasing the existing document/table. Capture original codec2 sidecar bytes/descriptor through SAME retained Sources, checking read identity against the already-validated file. Do not retain all original decision documents. No Python lifecycle/command/rejection/canonical replay enters this projection.

Export metadata exact top-level keys: `{schema_version:1,kind:'card-instance-final-validation-episode-payload',summary_sha256,episode_index,episode_id,viewer,episode_digest,binding,endpoint,bank,decisions,arrays,correspondence}`. `binding` is the existing full five-game-binding object (same exact existing keys/values). `endpoint` exact `{end_kind,outcome,reason}`; outcome/perspective remain original. `bank` exact `{actor,episode,initial_prefix_hash,event_records,terminal_prefix_hash}`; each ordered event record exact `{array_key,prefix_hash}`, denoting canonical original visible event JSON bytes and its subsequent prefix. `decisions` ordered accepted decisions, each exact `{frame_array_key,candidate_descriptor,candidate_array_key,selection}`. `selection` is existing closed `Selection` wire schema with full-precision JSON logprob/value, never float32 replacements. `candidate_descriptor` is the exact original codec2 descriptor; the descriptor's filename remains evidence, never an output location. `correspondence` exact `{episode_digest,frames}` where each frame uses the existing correspondence frame keys/order recipe. `arrays` uses existing exact `{key,dtype,shape,bank_index,element_offset,element_count}` descriptors with exhaustive nonoverlap/inventory checks.

`frame_array_key` points to canonical original `structured_wire.frame_dict` bytes (exact actor/episode/revision/interval/boundary/start-hash/payload/frame-hash fields); `candidate_array_key` points to exact original binary columns. Event/frame/columns byte arrays and shared raw frame/candidate token arrays have separate descriptor names; no sentinel data. Reuse Stage raw array keys/dtypes/shapes/ordering for tokens, with packet-local episode index0. Each atomic event/frame DTO record and codec payload is bounded by applicable record/source limits before copy/decode; every exported array/bank shard <=64MiB. Metadata >record cap or an unrepresentable packet fails rather than truncates or widens limits. Zero-decision episodes have real bank/endpoint facts, empty decisions and token inventory, and no fake frame/table/selection.

Python reconstructs `_CorrectedCardInstanceEventBankView` from immutable event bytes/prefixes; `structured_wire.parse_frame(...,layout=CORRECTED_CARD_INSTANCE_LAYOUT)`, `candidate_columns.decode_candidate_columns_v2` with exact original descriptor/full action contract/purpose/bounds, and `structured_wire.parse_selection`. Then use `structured_rollout.game_episode_records` with SAME validated actions/rules; original qualified_game binding is preserved without conferring eligibility. These common constructors check ownership/hash/columns, not another journal's transaction/lifecycle. No dummy EpisodeRecords and no alternate reader. Compare reconstructed episode/frame-table-selected digests and shared tokens to native evidence before accepting the packet. Native retains originals through reconstruction and final guards.

## Python forwarding, budgets, stages and cleanup

Keep `GameFinalValidationSource.selected_records` as real immutable64-tuple, with mutually exclusive Python snapshot and native collection-loan provider. Add a private guarded `FormalGameParent` forwarding method which obtains/retains its actual `_native_inputs`; do not expose a raw session handle or let callers construct a native provider from summaries. It requires active same-backend/binary/formal parent, one actual actor resource-borrow slot, complete final binding and exact plan. The loan stores SAME parent, actual issued token when pending, collection ancestors and actual native slot; it cannot reopen the parent. Source facts remain the current cloned Python facts format; the native summary is checked evidence, not a new public permission DTO. Keep Python-only path/output/default16 unchanged.

Before request canonicalization, independent pending hash, native Source construction, DTO spooling, JSON decoding, NumPy wrapping and Python64-tuple growth, reserve proposed new ownership against ONE parent joint budget. Parent `resident_bytes` excludes tracked external; `admit_external(n)` replaces that caller reservation and synchronizes actual native ownership. Do not reserve a second full allowance or count already-held banks twice. Include source/sidecar/inventory/control/caller/decode scratch, all retained earlier EpisodeRecords, pending evidence, current packet/export lease and proposed next DTO allocations before either copy. Use existing cumulative source/record/scratch/chunk constraints, source/record<=64MiB and arrays/shards<=64MiB; no budget increase. Full own records inherently consume memory: insufficient allowance refuses before decode without shrinking64/work/history/candidates. Cleanup-only `admit_external(0)` remains legal only after caller buffers retire; native may conservatively retain its lease until actual close.

Slot stages: Absent -> Inspecting(Failed latch armed) -> Inspected(next0) -> Exporting(Failed latch armed) -> PacketLive(next+1) -> Inspected once packet views/lease release are confirmed. Before another export, require all prior packet views dropped and perform original/pending guards; earlier reconstructed records stay charged. All64 exports -> Inspected(next64); no automatic qualified/complete flag. `recheck_final_validation` guards any healthy admitted state, including the final reconstructed64 tuple. `close_final_validation` moves to Closing before reportable work, then Closed ONLY after final guards, payload release, spool/core retirement and join confirmation. Any admitted error records SAME first error and permits cleanup only; best-effort notes cannot replace it or lose the owner. Cancellation keeps existing initiating-error priority; never extend deadlines. No close/final receipt from a late repaired artifact or empty retry after uncertain retirement.

Python Source close runs its usual final parent/pending/source/ancestor guards, releases decoded/native views and confirms native collection retirement BEFORE releasing the actor loan/external memory reservation. Healthy context then follows its existing terminal publication ordering; final CLI owned parent cleanup/lock release remains before publisher.finish. If cleanup is unconfirmed, retain SAME loan/Source/native/session/executor/publisher owner on the primary exception; outer parent/lock cannot be released as healthy. Real session/executor/lock confirmation remains observable during failed/expired cleanup. A NumPy base owner keeps its remaining RAM lease for escaped arrays, but grants no operational permission and cannot make healthy Source closure succeed while its packet is outstanding.
