This protocol was recorded before any enabled/disabled comparison data.
It supplements the accepted telemetry contract and the 24-run performance
matrix. Actual results are in the [verification record](../verification/rust-player-runtime.md).

Use the final MERGED/FROZEN producer/configuration for legacy and Rust runs.
Each calibration invocation is width192/seed17/epochs4/minibatch128/32 games and
ONE configured update, formation1ms. HPO D10000 therefore remains healthy
incomplete, never exact-final-D/fitness/quality data. Global RAM24GiB/CUDA12GiB;
recording5GiB for every calibration method; other explicit capacity settings are
identical to the final materialized scaling recipe. Preserve actual Source/
numeric/retention/audit conditions and record them, not an old executable.

Off means all new application diagnostics disabled, profiler off, SAME Rust
observer in --no-sampling mode for actual public-command spawn/wait/wall only.
On means complete application diagnostics plus observer100ms CPU/process and1s
PSS sweeps; profiler remains OFF. Both include actual whole invocation through
cold finalization. No live Python benchmark driver. Every run uses a fresh
namespace and retains originals/receipts/config/observer logs, including failures.

Block1 occurs atC8/B8 before the formal C8 population, with A/B each fixedW4:
legacy-off, legacy-on, A-off, A-on, B-on, B-off.
Block2 occurs only after the unchanged formal C8 selection, atC16/B16 before the
formal C16 population, using each scheduler's PREDEFINED selected W:
B-off, B-on, A-on, A-off, legacy-on, legacy-off.
This is at most12 one-update invocations (384 scheduled games), not an HPO search
or scientific campaign. Do not add repeat runs or retune cadence/histograms after
seeing performance without a new explicit recorded protocol decision; originals
and the formal populations remain separate.

frequency/reasons, stage/counter coverage, sampler duty/read/sweep spans, observer
